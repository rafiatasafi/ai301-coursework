# Rubric: is this plan ready?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diagnosis-matches-evidence | The plan's stated diagnosis/cause, read against the package's Repro evidence section | Pass only if the stated cause is consistent with every piece of gathered repro evidence (timings, control runs, before/after observations); fail if any repro evidence contradicts the stated cause; unclear only if the plan states no diagnosis at all | required |
| scope-bounded | The plan's full set of proposed changes (not just a stated exclusion line), read against what the Issue and Repro evidence show is actually broken | Pass if the proposed in-scope work is proportionate to fixing the reported behavior — one coherent change, even if it touches a few related spots; fail if the plan adds work the repro evidence does not call for (version bumps, cross-cutting abstractions, "while we're at it" redesigns, a CI matrix for a one-bug fix) or describes itself as addressing a broader pattern/pipeline instead of the reported issue; unclear only if the plan gives no description of what it will actually do | required |
| scope-exclusions-accurate | The plan's scope statement, wherever it describes what will NOT be done — phrased as "Not in scope", "Explicitly deferred", "leave to a follow-up", "won't touch", or similar — read against the Repro evidence and Issue | Pass only if each stated exclusion is actually true given the evidence (the excluded area really is uninvolved, or the plan gives a real reason — can't test it, out of the reporter's environment — for deferring it); fail if the evidence contradicts a stated exclusion (the excluded area is actually implicated); unclear if the plan states no scope/exclusions at all | required |
| executable-approach | The plan's approach/files section, read for named files or areas, a single chosen method, and concrete next actions | Pass if a stranger could start working immediately: specific files/areas are named and exactly one approach is chosen for each decision point; fail if a real decision is deferred to build time ("upstream or vendored, whichever is easier", "maybe also check X"), no files/areas are named, or the approach is only a restated goal ("speed it up", "make the crash go away"); unclear only if the plan gives no approach section at all | required |
| test-plan-targets-and-observable | The plan's Test plan section, read against both the plan's own stated diagnosis and the repro evidence's artifacts | Pass only if the proposed verification would actually exercise the stated cause (not just re-trigger the symptom through a different mechanism, and not a different mechanism entirely) AND names a concrete, checkable outcome (a specific command, assertion, log line, exit code, or metric threshold); fail if it tests a symptom instead of the cause, or if the named outcome is a subjective feeling ("should feel fast", "should look better", "should work well") rather than something a stranger could check pass/fail; unclear if no test plan is given at all | required |
| engages-thread-direction | The plan and plan comment, read against every maintainer (OWNER/MEMBER/CONTRIBUTOR) statement in Thread highlights that proposes, confirms, or rejects a direction | Pass if no maintainer direction exists in the thread, or if one does and the plan either follows it or explicitly diverges from it with a stated reason; fail if a maintainer direction exists and the plan silently ignores or contradicts it without acknowledgment; unclear is not available for this check — the thread either has a maintainer direction or it does not, and that alone decides which pass condition applies | required |
| discloses-ai-when-required | The plan comment, read against the repo-facts block's stated AI-related policy, for whether that policy demands a disclosure statement | Pass vacuously if the repo states no AI policy, or one that does not itself demand a disclosure statement (permissive-with-responsibility language, or an authorship-only rule); pass if the policy does demand disclosure and the comment includes a plain disclosure statement; fail only if the policy explicitly requires disclosing AI assistance and the comment contains none | required |

## Verdict rule

Ready (`accept`) only if every required check grades `pass`. A single `fail` on any required check holds the package at `reject`, regardless of how the others grade. `unclear` counts as `fail` on every required check — a plan whose diagnosis, scope, executability, test plan, thread-engagement, or disclosure cannot be verified from the package is not ready to post and build from.
